# M5Stack Core2 期限管理タスクアプリ

期限つきタスクを Core2 の画面に一覧表示し、**行をタップすると完了/未完了がトグル**される。
状態は本体の NVS に保存されるので、電源を切っても残る。
タスクの**追加・編集はスマホ/PC のブラウザから**行う（本体は一覧表示と完了操作に専念する）。

画面は2モードあり、右下のボタンで切り替える。

| モード | 中身 |
| --- | --- |
| 期限リスト | 自分で登録した期限つきタスク。NVS に保存される |
| 当日アクション | スプレッドシートの「当日アクションシート」を時間枠で表示。RAM のみ |

## 使い方（本体）

| 操作 | 結果 |
| --- | --- |
| 行をタップ | 完了 ⇄ 未完了 をトグル（ピッと鳴る） |
| `▲` / `▼` | スクロール |
| 3番目のボタン | 期限リスト: 未完了のみ ⇄ 完了込 / 当日アクション: 今の枠へジャンプ |
| 4番目のボタン | モード切り替え（当日 ⇄ 期限） |

**期限リスト**の左の色バーは期限の切迫度。
赤 = 超過 / オレンジ = 当日・6時間以内 / 黄 = 2日以内 / 緑 = 余裕あり / 灰 = 完了・期限なし。

**当日アクション**の左の色バーは担当（シートの M列）。
緑 = 山口 / 青 = 三木 / 橙 = 石黒。それ以外の名前は名前から決まる色を割り当てる。
担当は1行目の右にも文字で出る。分類（F列）は2行目に「分類・補足」として出す。
**今の時刻が入っている枠は背景が青くなり、青枠で囲まれる。**

行は**担当を混ぜて開始時刻の昇順**に並べる（同時刻はシートの並び順のまま）。
シート側の並びは時系列になっていないことがあるので、取り込み時に必ず並べ替える。

## 使い方（ブラウザ）

画面ヘッダーの2段目に出ているアドレスをスマホ/PC のブラウザで開く。
タスク名の入力・期限の日付/時刻指定・編集・削除・完了トグルができ、
操作するとすぐ Core2 の画面にも反映される。

### Wi-Fi の設定

初回はシリアルから一度だけ設定する。

```
wifi <SSID> <パスワード>
```

設定済みなら起動時に自動接続し、ヘッダーに `http://192.168.x.x` が出る。

**未設定・接続失敗（15秒）のときは本体が親機（AP）になる。**
スマホの Wi-Fi 設定から次の AP に繋げば、シリアルなしでも同じ画面が使える。

| 項目 | 値 |
| --- | --- |
| SSID | `M5Task-Setup` |
| パスワード | `m5task1234` |
| アドレス | `http://192.168.4.1` |

Wi-Fi 情報はタスクとは別の NVS namespace（`m5net`）に入れてあるので、`clear` でタスクを
全削除しても Wi-Fi 設定は消えない。消したいときは `wifi clear`。

なおタスク名は **UTF-8 で 63 バイト（日本語なら 21 文字）まで**。
超えた分は文字境界で切り詰める（途中のバイトで切って文字化けさせない）。

## 当日アクションの同期（tools/sheet_bridge.py）

スプレッドシートと本体を双方向に同期する常駐スクリプト。

```
python3 tools/sheet_bridge.py 192.168.100.37                      # 常駐
python3 tools/sheet_bridge.py 192.168.100.37 --once               # 1回だけ
python3 tools/sheet_bridge.py 192.168.100.37 --date 2026-08-30    # 日付を指定
```

| 向き | 間隔 | 内容 |
| --- | --- | --- |
| 本体 → シート | `--interval`（既定 2秒） | 本体で付けた☆と実測時間を A列・I列に書く |
| シート → 本体 | `--pull-interval`（既定 300秒） | 当日行を読み直して本体に流す |

**書き込みを先、読み直しを後**にしている。逆にすると、まだ書けていないタップを
シートの古い状態で上書きして消す。

読み直しの間隔を詰めてはいけない。1回あたり約2秒 GAS を動かすので、
5分間隔なら1日あたり約10分（Workspace の上限6時間の3%）だが、1分間隔だと約48分になる。

### シートの読み書き経路

`gcloud` の ADC は使えない。Google が既定の gcloud OAuth クライアントに
Sheets スコープを許可しておらず、`gcloud auth application-default login --scopes=...` は
必ず「アクセスがブロックされました」で失敗する
（[公式ドキュメント](https://docs.cloud.google.com/docs/authentication/troubleshoot-adc#access_blocked_when_using_scopes)）。

代わりに、**デプロイ済みの汎用 GAS ウェブアプリ（`~/.gas-webapp-url`）の
`readRange` / `sheetEdit` を借りている**。この GAS はすでに `spreadsheets` スコープを
持っているので、GAS 側のコードには一切手を入れていない。新しい公開エンドポイントも作っていない。

GAS は数分に一度 HTML のエラーページや 404 を返すことがある。ここで `sys.exit` すると
常駐が止まるので、2秒→4秒と間を置いて3回まで叩き直す。

**GAS の doPost を curl で叩いてはいけない。** リダイレクト後に再 POST して失敗する。
`urllib` を使うこと。

### Drive ダンプからの取り込み（予備）

`tools/import_actions.py` は Drive MCP のダンプから読む予備経路。**行番号が分からないので
書き戻しができない**（行番号 0 で送る）。動作確認用。

```
python3 tools/import_actions.py <Driveダンプ.json> <デバイスIP>
```

同じブックには未来アクションや作業ログのブロックもあり、行数だけで選ぶと 178 行のログを、
日付の新しさで選ぶと未来アクションを掴む。**最頻の日付が今日に一番近いブロック**を採り、
採用したブロックと次点を必ず表示する。

### 取り込みの生フォーマット

JSON ではなくタブ区切りにしているのは、デバイス側に JSON パーサを積まずに済ませるため。

```
POST /api/actions   Content-Type: text/plain; charset=utf-8

20260830
12	08:00	08:11	開発	デプロイ	新サーバー	山口	1
18	09:45	09:56	開発	修正依頼対応		三木	0
```

本体側のエンドポイントは他に3つ。

| | 内容 |
| --- | --- |
| `GET /api/actions` | 現在の一覧を JSON で返す |
| `GET /api/pending` | シートへ未送信の変更を `行番号 \t 完了 \t 実測分` で返す |
| `POST /api/ack` | 書けた行番号を受け取って未送信を落とす |

1行目が日付（YYYYMMDD）、2行目以降が
`行番号 \t 開始 \t 終了 \t 分類 \t タスク名 \t 補足 \t 担当 \t 完了(1/0)`。

行番号はシート上の行で、**書き戻しの鍵**になる（0 = 不明。書き戻さない）。
シートには同じ時刻・同じ名前で補足だけ違う行があるので、時刻と名前で照合してはいけない。

最大 160 枠。読めない行と上限超過はレスポンスに件数を返す（**黙って捨てない**）。

**完了はシートの☆が正。** 本体で付けたチェックはシートに書かれるまでの一時的なもの。
ただし読み直しは `actions[]` を作り直すので、**行番号で突き合わせて未送信ぶんは引き継ぐ**。
これをしないと、読み直しと同時に押したチェックが消える。

### 実測時間（I列）

本体でチェックすると、**前回チェックからの経過**をその行の I列に書く。完了時に押す前提。

- 起点はその担当の前回チェック時刻。まだ1件も無ければ**その枠の開始時刻（C列）**
- 前回チェック時刻は**担当ごと**に持つ（画面に3人分並ぶため）
- 12時間を超える値は書かない（日をまたいだ計算違いを持ち込まないため）

I列は**期間（duration）書式**のセル。文字列を入れると集計の数式が壊れるので、
「1日を1とした数値」で書く（33分なら `33/1440`）。セルの書式には触らない。

担当の色分けを確かめたいときは、複数人が混ざったサンプルを投げる。

```
curl -X POST --data-binary @tools/sample_actions.tsv \
     -H "Content-Type: text/plain; charset=utf-8" http://<デバイスIP>/api/actions
```

現在の枠のハイライトは、**取り込んだ日付が今日と一致するときだけ**出る。
昨日以前のデータを見ているときに「今ここ」を出さないため。

## 使い方（シリアル 115200）

```
pio device monitor          # ~/.platformio/penv/bin/pio
```

| コマンド | 説明 |
| --- | --- |
| `list` | 一覧表示 |
| `add <日付> [時刻] <名前>` | 追加 |
| `due <番号> <日付> [時刻]` | 期限変更 |
| `rename <番号> <名前>` | 名前変更 |
| `done <番号>` / `undone <番号>` | 完了 / 未完了に戻す |
| `del <番号>` / `clear` | 削除 / 全削除 |
| `seed` | サンプルタスクを入れ直す |
| `time <YYYY-MM-DD HH:MM[:SS]>` | 本体の時計合わせ（JST） |
| `now` | 現在時刻を表示 |
| `pending` | シートへ未送信の変更を表示 |
| `wifi` | Wi-Fi の状態とアドレスを表示 |
| `wifi <SSID> <パスワード>` | Wi-Fi を設定して接続 |
| `wifi clear` | Wi-Fi 設定を消して AP モードへ |
| `help` | コマンド一覧 |

**番号は `list` の出力の番号**（登録順）であって、画面に見えている行順ではない。
画面は期限順に並べ替えて表示するので、`done` する前に必ず `list` で番号を確認する。

日付は `2026-09-01` / `2026/9/1` / `9/1`（年省略＝今年）/ `none`（期限なし）。
時刻は `17:00`。省略すると終日扱いになり、残りは日単位で表示される。

```
add 2026-09-01 17:00 展示会の資料入稿
add 9/5 月次ミーティング準備
due 3 9/10 09:30
time 2026-08-22 10:00
```

## 時計について

**Wi-Fi に繋がっていれば NTP で自動的に合う**（同期できた時刻は RTC にも書き戻すので、
次からは Wi-Fi なしでも正しい時刻で起動する）。

シリアルに `[ntp] 30秒間 補正なし` と出るのは**異常ではない**。SNTP は時刻の補正が
必要なときだけ同期完了を返すので、既に合っていれば何も起きないのが正常。
ずれていれば数秒で直る。NTP を塞いでいるネットワークもあるので、繋がらない場合は
`time <YYYY-MM-DD HH:MM>` で手動設定する。

Wi-Fi が無いときは起動時に本体の RTC から時刻を復元する。RTC のバックアップ電圧が落ちている、または
読み出した時刻がビルド時刻より前／10年以上先といった明らかにおかしい値のときは、
ビルド時刻で暫定起動したうえで**ヘッダーを赤くして時刻の先頭に `!` を出す**。
この表示が出たら `time 2026-08-22 10:00` で合わせ直す。

## ビルド・書き込み

```
cd m5_task_manager
~/.platformio/penv/bin/pio run -t upload
```

`platformio.ini` の `upload_port` / `monitor_port` は接続中の Core2 に合わせて固定してある。
別のポートに挿し替えた場合は書き換える。`upload_speed` は 921600 だと転送が壊れたため 460800。

WiFi + WebServer を積むとバイナリが 2.2MB ほどになり既定のパーティションに収まらないので、
`board_build.partitions = huge_app.csv` を指定している（**そのぶん OTA は使えない**）。

## 実装メモ

- ライブラリは **M5Unified のみ**。旧 `M5Core2` は AXP192 決め打ちで Core2 v1.1（AXP2101）だと表示が出ないため使わない。
- 日本語は `fonts::efontJA_12/14/16`。ソースは UTF-8。
- 描画は全画面を `M5Canvas`（PSRAM 上の 320x240 16bit スプライト）に組んでから 1 回 `pushSprite` する。行単位で直接描くとちらつく。
- 時計は起動時に RTC から復元し、RTC 未設定なら `-D BUILD_UNIX_TIME=$UNIX_TIME` のビルド時刻で初期化する。
- **`M5.Rtc.setSystemTimeFromRtc()` は TZ を壊す。** 内部で `getenv("TZ")` の戻りポインタを保存したまま
  `setenv("TZ","GMT0")` するため、復元時に `TZ=GMT0` になる（時刻が 9 時間ずれる）。
  呼び出し直後に必ず `applyTZ()` で `TZ=JST-9` を再適用すること。
- Web UI は `src/web_ui.h`。`WebServer`（同期式）を `loop()` から回しているので、
  ハンドラは `loop()` と同じタスクで動く。排他は不要だが、`store` を書き換えたら
  必ず `commitChange()`（保存→並べ替え→再描画）を通すこと。`order[]` を作り直さずに
  描画すると削除直後に無効な添字を読む。
- Web の行 ID は `store.items` の添字。削除するとずれるので、
  API は毎回一覧 JSON を返し、ページ側はそれで描き直す。
- NTP 同期後に `M5.Rtc.setDateTime()` へ渡すのは **UTC**（`gmtime_r` で変換する）。
  `localtime_r` を渡すと RTC が 9 時間ずれ、上記の TZ バグが再発したように見える。
- **当日アクションは NVS に保存していない。** 出所がシートなので取り直せばよく、
  保存形式を増やすと移行処理がもう1本増えるため。`Store` には手を付けていない。
- **当日の行が0件のときは本体に送らない。** 日付が変わった直後はシートにまだ当日行が無く、
  そのまま送ると本体の表示が消える。
- **ハンドラ内で大きな配列をスタックに置かない。** `Action work[160]` は 20KB を超え、
  Arduino の loop タスクのスタック（8KB）を溢れて落ちる。`static` にすること。
- タスクの保存形式を変えるときは `STORE_MAGIC` を上げ、`load()` に移行処理を足す。
  現在 v1→v3 / v2→v3 の 2 経路が入っている（v2＝期限に時刻を追加、v3＝名前を 48→64 バイト）。
  **旧構造体（`TaskV1` / `TaskV2`）の `name` は必ずリテラル 48 で固定する。**
  `NAME_LEN` を参照させると定数変更で長さが変わり、旧データの長さ判定が全て外れて
  既存タスクが消える。
